# Ясна — прототип системы записи

Детская столярная мастерская «Ясна», Сургут. Два кабинета: мастер и родитель.
Тарифы и оплата, запись без ожидания, чеки, история посещений и оплат.

Публичный адрес: `https://serbaulia5.chatium.ru/yasna`.

## Вход родителя

1. Мастер открывает «Клиенты» → семью → «Ссылка для родителя».
2. Мастерская отправляет родителю готовую ссылку. Родитель просто открывает её:
   ни токен, ни код, ни пароль вводить не нужно. В интерфейсе нет поля для
   ссылки или авторизации.
3. Ссылка содержит секрет в fragment, но страница сразу убирает его из адреса и
   запоминает семью в `sessionStorage`.
4. Если ссылка не открылась, экран объясняет, что нужно попросить новую, и
   показывает демо-доступ для проверки прототипа.

В рабочей версии обмен токена идёт через
`POST /auth/access-link/exchange`, серверную cookie и CSRF.

## Оплата и запись

1. Родитель входит по ссылке и сразу видит расписание. Вкладка «Тарифы» идёт
   следующей после расписания.
2. В «Тарифах» можно заранее купить разовое посещение или абонемент. Кнопка
   «Купить» ведёт на отдельную страницу оплаты; там родитель проверяет состав
   и нажимает «Оплатить».
3. В календаре родитель выбирает день, занятие и ребёнка и нажимает
   «Записаться». Открывается окно записи:
   - если у ребёнка уже есть абонемент или разовое посещение — кнопка
     «Записаться» сразу создаёт активную запись;
   - если оплаты нет — в окне показываются тарифы. Родитель выбирает
     1 посещение или абонемент и нажимает «Перейти к оплате».
4. Открывается отдельная страница оплаты с составом заказа и суммой. Родитель
   нажимает «Оплатить»; после демо-оплаты запись создаётся сразу.
5. Мастерское подтверждение не требуется. Запись сразу активна, ребёнок
   появляется в журнале и расписании мастера.
6. После оплаты открывается экран «Оплачено» с суммой и записью. Чек появляется
   в «Истории оплат» только после того, как мастер прикрепит файл к платежу.

### Как считается оплата

- Абонемент: занятия в `Subscription.remaining`; списание — при отметке
  посещения в журнале.
- Разовое посещение: `Subscription.singleCredits`; списывается при создании
  записи.
- Запись без абонемента и без разового кредита невозможна: `createBooking`
  возвращает `PAYMENT_REQUIRED`.
- `createBooking` сразу ставит статус `confirmed` и добавляет ребёнка в занятие.

## Данные и устройство

- `shared/demo.ts` — типы и демо-данные: 8 семей, 10 детей, 18 занятий,
  абонементы, разовые посещения, платежи, счета, записи, уведомления, тарифы.
- `shared/use-demo.ts` — демо-хранилище. Общее для всех компонентов страницы,
  сохраняется в `localStorage["yasna.demo.v7"]`; изменения из другой вкладки
  подхватываются через `storage`. Сервер, Heap и настоящие сессии не подключены.
- `shared/use-parent.ts` — вход по токену из fragment, сессия семьи, выход.
- `components/ParentShell.vue` — кабинет родителя: 4 вкладки и уведомления.
- `components/ParentBookingSheet.vue` — выбор тарифа и переход к оплате (или
  мгновенная запись, если тариф уже оплачен).
- `screens/ParentCheckoutPage.vue` — страница оплаты тарифа, в том числе
  оплата с записью на выбранное занятие.
- `components/MonthCalendar.vue` — общий календарь мастера и родителя.
- Чеки — файлы в защищённом FileService, открытие и скачивание через
  `/yasna/receipt` с подписанной ссылкой на 5 минут.

## Соответствие `endpoint.md`

Реального HTTP-бэкенда по контракту пока нет, поэтому кабинет работает на
демо-слое с теми же сущностями и сценариями. Соответствие ручек:

| Контракт `endpoint.md`                     | В прототипе                                                |
| ------------------------------------------ | ---------------------------------------------------------- |
| `POST /auth/access-link/exchange`          | разбор `#token`, `familyByToken`, сессия семьи             |
| `GET /families/me`                         | семья и дети из `useParent`                                |
| `GET /public/schedule`                     | занятия месяца в календаре и на дне                        |
| `GET /lessons/:id/availability`            | `seats_taken` / `seats_available` в карточке               |
| `POST /bookings`                           | `createBooking` — проверка оплаты, резерв, активная запись |
| `POST /invoices` + `POST /payments/intent` | `payTariff` и `ParentBookingSheet`                         |
| `GET /families/me/attendance`              | `ParentHistoryPage`                                        |
| `GET /families/me/payments`, `/invoices`   | `ParentPaymentsPage`                                       |
| `POST /master/payments/:id/receipts`       | загрузка чека в `FinancePage`                              |
| `GET /receipts/:id/download`               | `/yasna/receipt?hash=…&download=1`                         |
| `GET /notifications`                       | `notificationsFor` в шапках кабинетов                      |

Отдельной ручки подтверждения мастером нет и не используется: оплата
происходит до записи, запись создаётся активной. `/yasna/requests` теперь
показывает записи только для просмотра.

## Ограничения прототипа

- Нет настоящего бэкенда, cookie-сессий, CSRF, идемпотентности и транзакций.
  Демо-состояние живёт в браузере.
- Ссылки доступа и сессии демонстрационные: токены лежат в демо-данных, срок
  действия и отзыв не проверяются. В рабочей версии — только хеш токена в БД.
- Оплата демонстрационная, без ЮKassa/СБП и вебхуков.
- Отмена и возврат родителем не реализованы; мастерского подтверждения нет по
  замыслу.
- Маршрут выдачи чека пока не проверяет роль пользователя; ссылка подписывается
  на 5 минут.
- Одновременные заявки не резервируют место на уровне БД.
- Демо-дата зафиксирована на 14 ноября 2026, «сейчас» — 12:00.
