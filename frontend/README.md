# Интерфейс «Ясна»

Самостоятельное Vue 3-приложение на основе предоставленных экранов Chatium. Рабочие исходники находятся в `src/`; папки `yasna-source-master` и `yasna-source-family` сохранены как оригиналы и не участвуют в сборке. Chatium для запуска не требуется. Данные загружаются из Go/Gin API и сохраняются в PostgreSQL. Локальной базы и демонстрационного входа в чужую семью нет.

## Запуск

Из корня проекта с уже настроенным `.env`:

```sh
docker compose up -d --build
```

Открыть **http://localhost:3000/yasna**. Логин мастера и пароль — заданные при первом запуске бэкенда (`MASTER_LOGIN`, `MASTER_PASSWORD`). Повторное изменение этих переменных не меняет пароль существующего пользователя.

Локальные настройки: `APP_ENV=development`, `APP_URL=http://localhost:3000`, `ALLOWED_ORIGINS=http://localhost:3000`, `COOKIE_SECURE=false`, `PAYMENT_RETURN_URL=http://localhost:3000/payment-result`. Используйте именно localhost, поскольку Origin должен совпадать с настройкой. Для публикации нужны HTTPS, соответствующие адреса и `COOKIE_SECURE=true`.

В разделе «Клиенты» раскройте семью и создайте персональную ссылку. Передайте её родителю самостоятельно. Создание новой ссылки отзывает предыдущие ссылки и сессии семьи. Ссылка действует 30 дней. Токен передаётся во фрагменте URL и удаляется из адресной строки после открытия; дальше используется серверная HttpOnly cookie. Чтобы одновременно проверять оба кабинета, открывайте ссылку родителя в другом браузере или приватном окне. Открытие ссылки в том же браузере завершает предыдущую сессию.

## Что подключено

- Расписание, создание занятий и запись детей мастером; проверка мест и пересечений на сервере.
- Семьи и дети, добавление семьи с датами рождения, выдача защищённой ссылки.
- Журнал: посещение, пропуск, отмена, исправление отметки с проверкой версии. Списание рассчитывает сервер.
- Абонементы, тарифы, денежный баланс, история оплат. Мастер может оформить абонемент за уже полученные наличные или закрыть существующий счёт наличными/переводом в «Финансах».
- Загрузка и замена PDF/JPEG/PNG чеков до 10 МБ; открытие файлов и внешних ссылок на чеки в обоих кабинетах.
- Родитель: свои дети, запись, отмена и перенос в блоке «Мои записи», посещения, оплаты, чеки, покупка абонемента и оплата открытого счёта через СБП.
- Уведомления и отметка прочтения. Обновление при загрузке приложения, после действия и кнопкой «Обновить данные».
- Правила группы: переключатели списания пропуска и переноса, срок бесплатной отмены. Сохранение создаёт новую версию с завтрашнего дня.

При создании занятия название сопоставляется с группой. Если группа новая, создаются группа и её начальные правила; цена разового посещения задаётся в форме. Остальные параметры правил доступны через API. При совпадающем названии используются существующие условия группы.

Онлайн-оплата требует тестовых ключей ЮKassa и доступного сервису HTTPS webhook. Успех показывает только подтверждённый сервером статус. Возврат на страницу сам по себе не начисляет занятия. При отсутствии ключей интерфейс показывает ошибку настройки; ручная оплата продолжает работать. Приложение не отправляет родителям ссылки или сообщения автоматически.

## Разработка

Node.js 22.12+ и npm. Бэкенд работает на порту 8080:

```sh
cd frontend
npm ci
npm run dev
```

Vite слушает порт 3000 и проксирует `/api` на `127.0.0.1:8080`. Если порт занят Docker-фронтендом, сначала из корня выполните `docker compose stop frontend`. Другой адрес бэкенда задаётся `API_PROXY_TARGET`. В production эту же роль выполняет Nginx. Секреты оплаты и БД никогда не передаются в сборку браузера.

`src/shared/api.ts` — fetch, cookie, CSRF, обработка ошибок и пагинация. `src/shared/use-demo.ts` — адаптер серверных моделей к исходным экранам; имя сохранено ради совместимости, демонстрационных данных внутри нет. `src/shared/demo.ts` содержит только типы и форматирование. `src/App.vue` — вход и переходы между разделами без полной перезагрузки.

## Проверки

```sh
npm run build
npx playwright install chromium
npm test
```

Браузерный тест требует запущенных сервисов на localhost:3000, локального `.env`, тарифов и хотя бы одного будущего занятия со свободным местом (например, после `backend/scripts/seed-demo.sh`). Проверяет страницы мастера, отдельный мобильный кабинет родителя и разграничение доступа, запись и отмену, ручную оплату счёта и её отображение у родителя. Тест создаёт вымышленную семью «Проверка интерфейса…», счёт и оплату в используемой БД; запускайте его на демонстрационной базе. Эти записи сохраняются для просмотра. Реальных платежей тест не делает.

## Ограничения интерфейса

- Расписание родителя загружается за последние 30 и следующие 60 дней; собственная история дополнительно собирается из всех записей.
- Карточки ребёнка показывают суммарный остаток активных абонементов; применимость к конкретной группе, дата и правила проверяются сервером. Планируемые и истёкшие абонементы не входят в этот остаток.
- Оценки детей не предусмотрены API; доступна посещаемость. Полный аудит исправлений хранится на сервере, в экране показывается текущая отметка.
- Создание тарифов, полное редактирование групп и занятий, все параметры правил, CSV и служебные операции остаются доступны через API/Postman; отдельных форм для них пока нет.
- Перенос и запись не означают оплату. Если на сервере нет подходящего абонемента, списание и задолженность определяются его правилами.
- Это локальное подключение; исходные опубликованные страницы Chatium не изменены.
